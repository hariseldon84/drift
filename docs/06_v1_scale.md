# Drift Browser — V1 Scale

## Objective
Turn the commercially viable V0 into a browser that approaches category leaders on browser completeness while expanding the object/action moat beyond product comparison.

V1 should not merely add features. It should prove that the object model generalizes.

## V1 Product Position

> **Drift understands the things inside webpages — and lets you work with them across the web.**

## 1. Browser Benchmark Expansion
Close meaningful gaps versus Chrome/Dia/Edge/Vivaldi:
- robust sync
- profiles
- vertical tabs option
- richer tab groups
- polished split view
- translation
- PiP/media quality
- stronger password/autofill UX
- polished downloads
- browser settings completeness
- keyboard customization where feasible
- accessibility audit
- enterprise-ready policy groundwork without enterprise GTM

## 2. Reliability at Scale
- better state persistence
- restart checkpoints
- tab RAM attribution improvements
- recoverable-memory estimate
- archive recommendation model
- protection for active forms/media/meetings
- resource policy adjusted by mode
- empirical stability-risk scoring if accuracy is demonstrated
- cross-device session handoff if sync architecture permits

## 3. Research Mode
V1 should introduce the second flagship mode.

Capabilities:
- collect passages/articles/tables into source tray
- semantic source dedupe
- novelty analysis within explicit research corpus
- source provenance
- structured notes from selected objects
- contradiction candidates
- selected-source synthesis
- export with source links

The signature V1 Research feature should be:
> **Show me what's new across these sources.**

## 4. Auto Pilot
Ship after Compare and Research modes are stable.

User explicitly activates Auto Pilot.

System:
- detects current job
- chooses Compare/Research/Normal behavior
- exposes current mode subtly
- uses confidence threshold
- accepts one-click correction
- does not constantly ask permission to change low-risk UI behavior

## 5. Object Model Expansion
Add richer types:
- company
- person
- chart
- code block
- form
- video segment
- paper/publication
- flight
- hotel
- job listing
- software/package

Not every type needs bespoke workflows immediately.

## 6. Object Identity
Improve cross-site canonicalization:
- product identity
- company identity
- publication identity
- travel listing identity

Use:
- deterministic identifiers
- structured metadata
- fuzzy matching
- embeddings
- local model
- cloud fallback only where needed

## 7. Action Engine Expansion
V1 actions:
- batch downloads
- safe form fill
- navigate
- copy structured output
- save comparison/research set
- search missing information
- reorganize tabs based on current operation
- close semantic/URL duplicates with user review
- execute site interactions with permission tiering

No silent purchase or submission.

## 8. Action Composition
Expose simple chains without forcing users to build automations.

Example:
Select laptops
→ Compare
→ Find missing battery values
→ Filter < ₹100k
→ Export

Internally these are typed actions.

## 9. Saved Objects / Early Live Objects
Introduce:
- saved object snapshot
- saved comparisons
- object provenance
- refresh command

Live refresh can begin with narrow object classes such as product prices.

## 10. Local Memory
V1 local memory can support:
- "you compared this before"
- "you already opened this source"
- object history
- research-set history
- saved comparison recall

Must include:
- sensitive-site exclusions
- delete controls
- clear on-device vs cloud boundary

## 11. Model Architecture
V1 should have a mature router:
Rules
→ classical ML
→ local embedding/classifier
→ small local LLM/VLM
→ cloud model

Target:
reduce cloud dependence per workflow over time.

## 12. Extensibility Preparation
Do not necessarily launch marketplace yet, but stabilize:
- action schema
- object schema
- mode manifest
- permission model

This enables later:
- custom actions
- custom modes
- third-party skills
- external agents
- MCP/CLI

## 13. Commercial Expansion
Potential Pro differentiators:
- advanced Research Mode
- larger source sets
- richer cloud synthesis
- saved/live objects
- advanced comparison enrichment
- high quotas
- advanced local-model packs if valuable

## 14. V1 Benchmark Scorecard

### Against Chrome
- core browsing completeness
- extension compatibility
- stability
- import/sync
- performance

### Against Dia
- contextual AI usefulness
- tab organization
- memory
- perceived modernity
- task completion

### Against Opera Neon / Comet
- agent/action capability
- cross-source operations
- trust/permission clarity

### Drift-specific
- object-recognition precision
- selection-set completion rate
- structured-field accuracy
- object identity precision
- novelty-analysis usefulness
- action completion rate

## 15. V1 Exit Criteria
V1 is ready for broad scale when:
1. Drift can be used as a primary browser without frequent fallback to Chrome.
2. Compare Mode is polished and defensible.
3. Research Mode proves the object model generalizes.
4. local-first architecture materially reduces cost/privacy exposure.
5. action permissions feel trustworthy.
6. retention is driven by differentiated workflows, not novelty.
7. browser reliability is at least credible against category leaders.

## What V1 Still Should Not Become
- email client
- VPN bundle
- Notion clone
- generic desktop agent
- enterprise governance suite
- prompt marketplace disguised as browser UX

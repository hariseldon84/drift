# Drift Browser — Product Thesis & Innovation Pillars

## Product Thesis
Drift should not win by being "another AI browser." Its ambition is to become the browser where the web itself becomes manipulable.

The product thesis is:

> **Drift is the browser that understands what you see and helps you act on it.**

Drift keeps the familiar mental model of the modern browser — tabs, address bar, extensions, history, bookmarks — but adds a native intelligence layer capable of recognizing meaningful webpage objects, collecting them across tabs, transforming them into structured information, and safely acting on them.

Reliability and resource intelligence are required to earn trust, but **Object Understanding + Action Engine** is the intended moat.

## 15 Non-Negotiable Principles

### 1. Familiar first
A Chrome user should understand Drift immediately. Do not demand a new browsing mental model merely to access the innovation.

### 2. Chrome-class JTBD parity
Switching to Drift must not create a meaningful capability deficit for mainstream desktop browser jobs.

### 3. Normal browsing is sacred
Webpages behave normally by default. Drift's intelligence must not cause accidental selections, drag states, overlays, or mode changes.

### 4. Recognition can be always-on; interaction must be invited
Drift may quietly understand objects in the page. It should expose object interactions only after explicit user intent or an explicitly selected Auto Pilot mode.

### 5. The webpage is a field of actionable objects
Products, tables, charts, passages, people, companies, forms, videos, images and other meaningful elements are not merely pixels or DOM nodes; they can become browser-native objects.

### 6. Multi-object and cross-tab operations are first-class
The product should become more useful when users collect and act across multiple tabs rather than merely chatting with one current page.

### 7. Object Understanding + Action Engine is the moat
Do not mistake an LLM sidebar, summarization, tab groups, memory, sleeping tabs or agent navigation for sufficient differentiation.

### 8. Local first; cloud only when necessary
Use deterministic methods, conventional ML and local models before cloud inference whenever quality permits.

### 9. Use the simplest intelligence that works
Rules beat ML when rules are sufficient. Classical ML beats GenAI for prediction/classification jobs that do not require generative reasoning.

### 10. Human authority over consequential actions
Drift may automate reversible browser-local actions. Sending, submitting, purchasing, deleting and other consequential operations require clear user approval.

### 11. Warn early; intervene late
Resource intelligence should anticipate instability and advise first. Drift may autonomously protect the browser only when necessary and in reversible ways.

### 12. Never auto-archive user work
Active/Warm/Cold transitions may be automatic. Archive is session-specific, browser-suggested and human-triggered.

### 13. Modes are explicit behavioral contracts
Normal, Compare, Research and Auto Pilot modes exist to make advanced capabilities predictable. Auto Pilot itself must be explicitly selected.

### 14. Intelligence should reduce cognitive load, not create another control system
Avoid dozens of persistent controls, model selectors, prompts and status indicators. Powerful capability should remain visually quiet.

### 15. Be willing to kill commodity features as differentiation claims
If Chrome, Edge, Dia, Vivaldi, Comet, Brave, Opera or another strong competitor already solves a job well, keep parity where needed but do not call it Drift's innovation.

## Current Innovation Hierarchy

### Tier 1 — Intended moat
- object recognition
- object identity across sites
- contextual object actions
- cross-tab selection sets
- object tray
- structured cross-page extraction
- action composition
- safe execution

### Tier 2 — Strong differentiators if execution is excellent
- Compare Mode
- Research Mode
- Auto Pilot mode selection
- "what is new relative to what I already read?"
- duplicate-information detection
- live objects
- local-first browser memory

### Tier 3 — Trust / usability layers
- Active / Warm / Cold tabs
- session archive
- resource observability
- crash-risk mitigation
- state continuity
- migration from Chrome

### Tier 4 — Table stakes
- extensions
- history
- passwords
- bookmarks
- profiles
- private mode
- downloads
- devtools
- sync
- basic tab management
